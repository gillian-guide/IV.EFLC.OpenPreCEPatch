# Improvements over the original loader

This tree keeps every original write, gate and arm order **of the install-time
game-image options it implements**, proved by `tools/parity_report.py 9` (the
84-key per-key scoreboard on 1.0.8.0), `tools/dump_matrix.py` (nine on-disk
builds, full and per-option cells) and `tools/verify_bodies.py` (the transcribed
bodies, instruction for instruction). The oracles are install-time only; they do
not execute hook bodies and they do not map `xlive.dll`, so:

| oracle | covers | does not cover |
|---|---|---|
| `tools/parity_report.py 9` | the per-key write set on 1.0.8.0: 84 keys, five measured deltas reported apart | runtime hook-body writes, `xlive.dll`, the launcher process probe |
| `tools/dump_matrix.py` | the same write set on the nine on-disk images, in the full and the per-option cell | same limits |
| `tools/verify_bodies.py` | every transcribed body, one manifest row each, with absolute operands compared as slots | the pieces rebuilt in C++, which have no proof row |
| `native tests` | the config contract, the failsafes, the launcher bytes/gate, the warnings' probes, the caches | live game execution |
| `tests/parity/applicability.tsv` | 84 keys x 12 builds: the build mask each arm gates on | behaviour |

The entries below are the deliberate differences: each one only changes what
happens when the image or the INI does not match what the original assumed, and
each leaves the original path reachable or trivially revertable. The 15 keys
OpenPreCEPatch removed or moved to XLivelessAddon are out of the catalogue
(`AddOptionsInMenu`, `FixPCIDKickbug`, `ForceDynamicShadowsEverywhere`,
`HighQualityReflections`, `MiscFixes`, `NoPhysicsSleep`, `RemoveBoundingBoxCulling`,
`RemoveUselessChecks`, `BorderlessWindowed`, `DoNotPauseOnMinimize`,
`LocalSettingsPath`, `SkipIntro`, `SkipLauncher`, `SkipMenu`, `VRAMFix`);
`tools/gen_options.py` refuses to emit them, and a row for one of them in an old
flat INI is never read.

## Absent-key defaults: the arm fallback vs the shipped INI

Two defaults are legitimate and are not made equal:

* an **absent key** uses the arm fallback, which is the catalogue's `absent`
  column: the default the original loader passed at that read site, recovered per
  key and committed as `source/options.inc` (84 rows, generated by
  `tools/gen_options.py`). CTest `zp_catalogue_drift` fails if the file drifts
  from its inventory, and `Catalogue::Read` hands that default to
  `Config::Integer`, so an absent key and an unparseable one land on the same
  value.
* a **present key** uses the value the document carries. The shipped install reads
  the grouped `IV.EFLC.OpenPreCEPatch.ini`; the scoreboard reads the flat
  `tests/parity/ZolikaPatch.ini` (`tools/gen_ini.py`, CTest `zp_ini_drift`).
  Fifteen numeric options carry a different value in the two files
  (`BetterMPSync`, `CopSirensFlag`, `EpisodicVehicleSupport`,
  `EpisodicWeaponSupport`, `ImprovedShaderStreaming`, `InfiniteCarBottomDistance`,
  `MovingPlaneParts`, `MovingSteeringWheelSupport`, `PipeBombDropIconSupport`,
  `PlaneCrashFix`, `PopupHeadlightsFlag`, `RemoveGFWLUpdatePopup`,
  `RestoreDeathMusic`, `ShakingEngineBlock`, `TryToSkipAllErrors`), so deleting one
  of those lines restores the arm fallback. No behaviour changed to produce this
  split; it is the original's own shape made explicit. Two more differences are
  the surfaces themselves: the grouped file carries the three oPCEP-only keys
  (`GFWLProtectionDisabler`, `SteamAchievements`, `RemoveModChecks`) and leaves
  `OverrideGTADatPathTo` on its shipped path, while the flat file carries the two
  recovered mod-check keys and comments `OverrideGTADatPathTo` out.
  `RemoveModChecks` is the unified alias: `ModChecksEnabled` answers true for any
  of the three recovered keys or for `RemoveModChecks` read outside the catalogue.

Eleven keys also carry a catalogue `shipped` value that differs from their
`absent` fallback (`CarDynamicShadowFix`, `DualVehicleHeadlights`,
`ForceCarHeadlightShadows`, `BuildingDynamicShadows`, `RestoreDeathMusic`,
`NoLoadingSleep`, `RemoveRGSCLoginRequirement`, `VSyncFix`,
`Patch6and7RemoveModChecks`, `Patch7RemoveModChecks`, `LaunchWithPlayGTAIV`).
`CarDynamicShadowFix` is the documented exception the scoreboard names: its
fallback is 0 and both INIs ship 1, so deleting its line is the only way to reach
the original's 0.

**The generated table is the option catalogue.** There is no second typed
`OptionSpec`: the defaults live in `source/options.inc`, which
`tools/gen_options.py` generates from the recovered behaviour inventory, and
`tools/gen_ini.py` serialises the same table into the flat parity INI. A typed
table would duplicate the defaults and could drift from the code that actually
reads them; the generated file cannot. The shipped grouped INI is the user-facing
surface, and `Catalogue::Read` is the only reader.

## Arm writes

Arm writes are direct `injector::MakeJMP` / `MakeCALL` / `MakeNOP` / `WriteMemory`
calls, as in FusionFix: there is no wrapper between an arm and the injector, and
`source/patch.ixx` keeps only the two primitives that need more than a direct call
(`raw_mem`, `IATHook`). A missing signature is the arm's own clean skip (the
original's behaviour), and the install-time failsafes are unconditional:
`Failsafe::Missing` refuses an arm whose preamble pointer a body would
dereference, `Failsafe::Site` refuses a write outside the image,
`Failsafe::Body` refuses a jump to an unresolved body, and `ExpectMatchCount`
refuses a partial multi-site install. A transcribed body is never rewritten, so
the game keeps its own un-patched path. The 18-cell dump matrix proves the write
set is unchanged.

## ImprovedShaderStreaming and NewMemorySystem

`docs/performance.md` describes both hot-path replacements: the game function or
allocator they replace, the exact write contract, and the deliberate changes.
The two compatibility/robustness changes are:

* `ImprovedShaderStreaming` replaces only the two first `LookupShader` calls and
  leaves the two chain jumps the earlier patch wrote. Those jumps were only a
  miss-path speed-up, and the bytes they overwrite are part of LibertyCityPlates'
  address signature: that mod aborts its whole address setup -- so its shaders
  never load -- when the signature stops matching. A miss now falls through the
  game's own name chain. This is one of the five measured deltas.
* `NewMemorySystem` keeps the original's *range* ownership answer at page
  granularity, rejects a 32-bit allocation-size overflow, allocates from a private
  `HeapCreate` heap, and hands a pointer it did not allocate back to the captured
  original allocator instead of reading its own base-offset header from it. The
  page map is what prevents the `MMA10` fatal: an interior or already-freed
  pointer is still "mine", so the multi allocator never finds an owner-less free.

## Config: the original grammar, one read, no throw

`source/config.ixx` reads the file once and parses it with the original's grammar
-- feather-ini-parser 1.41, the reader the original linked statically -- quirks
included: the 255-byte line buffer and the `failbit` spin a 256th byte causes,
`#`/`//` comments only at the start of a line, `strtok`-on-`=` keys, values that
keep their spaces, empty values not stored, last duplicate wins, a re-opened
section starting empty, and the key-before-section null store. `Feather::LoadGrouped`
normalises the shipped grouped file first (trailing `//` and `;` comments, CRLF
folded) so no line reaches the buffer fault; the flat file keeps the original
grammar untouched.

The read never throws: `Config::Integer` parses the stored text with `strtol`'s
base-10 prefix grammar and falls back to the arm's default on anything else,
logging `config: invalid value for <key>: "<value>", using default <default>`;
`Config::Float` does the same through `strtof` and `errno`, and a bad
`[PopupLightAngles]` / `[HeadlightConeOffsets]` row keeps its hash and zero value
with one line per row. `std::stoi` survives only as the conversion of the
caller's default text (always numeric), never on the stored value.

Everything a legal INI can observe is unchanged: the section search order
(`Options` first, then the subsystem groups OpenPreCEPatch ships), last-duplicate-
wins, the exactly-`1` gate (`"1abc"` is 1, `"0x2"` is 0), CRLF folding, and the
whole-line `#`/`//` comments (the shipped file's `;` lines are dropped by
`LoadGrouped` before parsing). The first-run creation and legacy import
(`Config::WriteGrouped`, `dllmain.cpp`) and the FusionFix overlap gate
(`Config::kFusionFixConflicts`, 31 keys) live in the same module: they answer the
same "what does this INI say?" question. Tests: `zp_tests` (`TestConfig`),
`zp_config_guard`, `zp_shipped_ini`, `zp_import`, `zp_model_tables`.

## Launcher slots: exactly the original's two

`Launcher::Install` rewrites the two `LaunchGTAIV.exe\0` name slots the original's
handler patches, on the five builds the handler's switch covers (1.0.0.0, 1.0.4.0,
1.0.6.0, 1.0.7.0 and 1.0.8.0), and only when the process list holds a live
`PlayGTAIV.exe` (the handler's own `sub_10003A10` walk). Both slots live in
`.rdata`, outside the executable range `find_pattern` covers, so the arm scans the
whole image. The arm requires **exactly two** matches and every hit must be one of
the recovered RVAs: zero, one or three-or-more matches log
`arm LaunchWithPlayGTAIV name slots: N match(es), expected 2: skipped` and leave
the image untouched, so a modded image cannot make this tree write a slot the
original never wrote. The native test covers the two-hit case plus the 0/1/3-hit
skips (`zp_launcher`); `zp_launcher_dump` measures the write set on all nine
images through the real pipeline.

## Multi-hit arms: expected site counts (P13)

The same guard covers every multi-match arm whose original read or patched a
**fixed** set of sites: `ExpectMatchCount` compares the scan's result count with
the recovered count, and a different count logs
`arm <name>: <what>: N match(es), expected M: skipped` and installs nothing (a
partial multi-site install is worse than no install). Guarded arms:

| arm | expected sites | evidence |
| --- | --- | --- |
| `BuildingDynamicShadows` hash pair | 2 | the two published model hashes the shim compares against |
| `NoImpostorHeightCutoff` | 2 | the two recovered literal sites |
| `BenchmarkFix` | 2 | the two benchmark entries |
| `EpisodicVehicleSupport` (component window) | 2 | the two recovered NOP sites |
| `EpisodicVehicleSupport` (episode test) | 2 | the two recovered NOP sites |
| `LaunchWithPlayGTAIV` | 2 | the two launcher name slots (see above) |

`StartupTimeFix` is deliberately **not** guarded: it walks every match of its
literal and patches each one (three on 1.0.8.0), so the hit count is image data,
not a recovered per-build constant.

## The install tiers

`source/common.ixx` owns FusionFix's `Event<Args...>`, and `source/loader.ixx`
owns the three `Event<>` tiers (`PublishEvent`, `InstallEvent`, `PostEvent`) plus
the option gate. Each feature module subscribes its arms from its own
`Register<Key>` function, and `dllmain.cpp` calls those registrations in a fixed
order (`RegisterStability`, `RegisterVehicles`, `RegisterGraphics`,
`RegisterLauncher`, `RegisterLoading`, `RegisterAudio`, `RegisterMisc`,
`RegisterOoc`) before `Loader::Run`. There is no `Phase` enum, per-arm schedule
table or dependency graph.

The publish tier is load-bearing: a site's original bytes and resume are read
before any install overwrites them, and a site write destroys the signature a
later publish would scan for. Inside a tier the handlers run in subscription
order, which is the order the driver registers the modules. An arm runs only when
`Loader::Enabled` answers true: the key must be in the catalogue, the classified
build must be in the key's mask, and the stored value must be exactly `1`. An
`unknown` build (id 0) is in no mask and installs nothing.

## Hook-body fidelity after the module split

The hook bodies live with the modules that install them, in a marked tail, so a
module reads top to bottom: patterns, published state, readable installers, then
the transcribed bodies. The transcribed machine-code bodies keep their
instruction-for-instruction contract: `tools/verify_bodies.py` compares a
baseline and the current ASI after normalising module addresses, lambda tags and
EH handlers, and requires every manifest row in `tests/bodies.tsv` to be
instruction-identical (CTest `zp_body_proof`). The proof compares absolute
operands as slots, and a registered table (`Bodies::RegisterTable`) by its
contents, so a body that reads a recovered table is transcribed like any other.
The candidate VA each row needs comes from the linker map, which is why
`ZP_LINK_MAP` is on by default.

A piece is rebuilt in C++ instead of transcribed when its instruction stream
cannot be compared: an exception frame (`__try`/`__except`), a `/GS` cookie with
a thread-safe static guard, or C++ container plumbing. The rebuilt pieces
-- the native layer's two guarded entries (`0x100038E0` / `0x10003980`), the
OutOfCommissionFix init, the SpeedupBugFix body and the three NewMemorySystem
arena methods (allocate `0x10038360`, free `0x10038430`, membership `0x100385A0`)
-- have no proof row; their evidence is behavioural (`zp_native_guard`,
`zp_ooc_init`, `zp_speedup_clock`, `zp_nms_arena`).

## Startup warnings: task dialogs, loader probe, single instance

The original opened message boxes from `DllMain`. The warnings are now
FusionFix-style task dialogs, and each is gated by an actual probe instead of a
proxy:

* **Presentation.** `source/warnings.ixx` shows `TaskDialogIndirect` with the
  common-controls 6.0 manifest the ASI embeds (`source/warnings.manifest`,
  `source/warnings.rc`): the game executable carries no such manifest, so
  `CreateActCtx`/`ActivateActCtx` are held around the call. When that fails the
  code falls back to a plain message box. The call is synchronous, like the rest
  of the startup path.
* **Old ASI Loader.** The loader is identified by Ultimate ASI Loader's
  `IsUltimateASILoader` export, and a version resource older than **6.9.0** is
  refused with a warning; a loader without the marker is reported the same way.
  The probe and the threshold are pinned by `zp_loader_info`.
* **Unsupported game version.** 1.2.0.1-1.2.9.99 are refused except **1.2.0.43**,
  the one Complete Edition build this tree has recovered gates for. The dialog
  states the downgrade/accidental-install case and the process exits with the
  original's `0x8000FFFF`.
* **Loaded twice.** A process-wide named mutex
  (`Local\IV.EFLC.OpenPreCEPatch-<pid>`) is claimed before anything is installed;
  a second copy of the ASI (a renamed duplicate, or two loaders with their own
  copies) gets the "loaded twice" dialog and does nothing.
* **FusionFix notice.** `IV.EFLC.OpenPreCEPatch.fusionfix-notice.txt` is rewritten
  on every launch with the enabled-but-gated options; the dialog is shown only
  while the file does not exist, so it stays one-time and deleting the file
  restores it.
* **ZMenuIV guard.** The original's `sub_10052300` guard is kept in
  `warnings.ixx` (`CheckZMenuVersion`): a loaded `ZMenuIV.asi` that exports
  `GetZMenuVersion` must report at least 220625 (`0x35DD1`), otherwise the
  original's message box and `TerminateProcess` run. The rebuild zeroes the two
  out-parameters first, so a library that writes nothing is refused
  deterministically instead of comparing whatever the caller's stack held; that
  one input is the only delta, and it is the reason this guard is listed here.
  An absent module or export continues, exactly as in the original.

## The baseline's two omissions

Two keys are excused from the scoreboard on specific builds because the stored
baseline is incomplete, not because this tree is. `tests/oracle_verified.tsv`
names each row with its build list, and `tools/check_oracle_verified.py` (CTest
`zp_oracle_verified`) refuses a row that names a build the catalogue mask does not
allow or a build the measured omission does not cover.

### The @noE fill: CarDynamicShadowFix on 1.0.0.0 and 1.0.4.0

On the two builds where pattern E is absent, the original writes a six-byte
`90 90 90 90 90 90` fill at the C anchor's +0x3E, and this tree writes it too.
The stored baseline has no row there because the reference tree's
`ApplyCarDynamicShadowFixNoE` pass was defined but never wired into the dump that
produced it. The row is therefore per key and per build, and the key is scored
normally everywhere else -- it is closed on 1.0.8.0.

### Patch7RemoveModChecks: the OR, an alternate handler

The original has no Patch7 handler of its own: `0x100523C0` ORs
`Patch7RemoveModChecks` into `Patch6and7`'s handler `0x10044710`, so a Patch7-only
INI runs the full 16-byte (1.0.6.0) / 21-byte (1.0.7.0) write set. The stored
baseline records the reference tree's own smaller 5-byte / two-jump, 10-byte arm
instead, so the key is excused on 1.0.6.0 and 1.0.7.0 only, and the baseline's
write set is a strict subset of this tree's.

## Backlog (documented, not gates)

These are recorded as unproven rather than as gates; nothing in CTest fails on
them:

* `GFWLProtectionDisabler` and `SteamAchievements` need a live `xlive.dll` and a
  Steam client; only their decisions, tables, guards and refusal paths are
  measured offline.
* The warnings dialogs are exercised by their predicates and the embedded
  manifest by `zp_pe_check`, not by a UI run.
* The garage prologue and the cutscene callee are proved at the write-set level,
  not by a live cutscene/garage A/B.
* NewMemorySystem's private heap and original-vtable capture are exercised on the
  process heap in `zp_nms_arena`; a live game run is still the only proof of the
  allocator swap.
* The OutOfCommissionFix archive is compared by pointer/state reuse, not by a
  live mount.
* The duplicate publish/install signature scans remain; a cross-tier cache would
  be unsound after an earlier install, so the startup cost is measured rather
  than cached.

The measurement tools that need the nine on-disk images and the stored baselines
(`tools/parity_report.py`, `tools/dump_matrix.py`,
`tools/single_key_matrix.py`) are run by hand; the repository does not carry
those inputs. CTest registers only the checks whose inputs exist
(`zp_dump_empty`, `zp_launcher_dump`, `zp_body_proof`, `zp_body_proof_selftest`,
`zp_signature_parity`, `zp_relocated_literals`, `zp_salt_probe`,
`zp_save_walk`).
