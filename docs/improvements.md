# OpenPreCEPatch improvements in this tree

This tree ships as OpenPreCEPatch: the OpenPreCEPatch changes are **compiled in**
on top of the readable-fusion code, and the keys OpenPreCEPatch removed or moved
to XLivelessAddon are out of the 85-key catalogue. The source-level audit below
was made against `openprecepatch/source/*` and
`openprecepatch/data/plugins/IV.EFLC.OpenPreCEPatch.ini`, not against its prose
docs; where the prose and the code disagree, the code is quoted here.

There is no runtime improvement switch. Git is the rollback: the integration
commit and the later audit-fix commit each end with a `Revert:` line and a tag.
The shipped INI is OpenPreCEPatch's grouped file; the flat `ZolikaPatch.ini`
stays only as the parity/legacy configuration the oracle tools use.

## 5. Measurement

```
ctest --preset release                       # 34 targets, all green
python tools/parity_report.py 9              # 80 closed, 5 expected deltas, 0 open
python tools/dump_matrix.py                  # 9 builds x (full, per-option)
python tools/gen_applicability.py --check
python tools/check_signature_parity.py --game ../game_refs
python tools/check_relocated_literals.py --game ../game_refs
python tools/check_oracle_verified.py
```

`parity_report.py` reports the five retained arms that deliberately write a
different set (GarageModelFix prologue, BuildingAlphaFix `jnz`-only,
CutsceneFixes callee, ImprovedShaderStreaming two calls, RemoveGFWLUpdatePopup's
shipped default) as `DELTA`, apart from `open`; the five reasons are in the tool
and in section 4. On 1.0.8.0 that is **80 closed / 5 delta / 0 open**.

The 18-cell dump matrix is retained as the write-set check for the 85 retained
keys. With the failsafes compiled in, the 1.0.0.0 NoImpostor cell no longer
faults: the P13 guard refuses the partial install. The regenerated matrix has
`differing 0` on all nine builds; the full cell's `missing` rows are the bytes
the 14 removed keys and the five deltas no longer write, which is expected, and
the per-option cell reports 74-80 of 85 closed (the five deltas are the rest).
The run must not overlap a build: each cell reads `zp_dump.exe`, and a relink
mid-run gives one cell a different body layout.

## 6. What is deliberately still unproven

- `GFWLProtectionDisabler` and `SteamAchievements` need a live xlive.dll and a
  Steam client; only their decisions, tables, guards and refusal paths are
  measured offline.
- The warnings dialogs are exercised by their predicates and the embedded
  manifest by `zp_pe_check`, not by a UI run.
- The garage prologue and cutscene callee are proved at the write-set level, not
  by a live cutscene/garage A/B.
- NewMemorySystem's private heap and original-vtable capture are exercised on
  the process heap in `zp_nms_arena`; a live game run is still the only proof of
  the allocator swap.
- The OutOfCommissionFix archive is compared by pointer/state reuse, not by a
  live mount.
- The FCHS checker's own null guards are not added; its lookup is covered by the
  shared memo.
- The duplicate publish/install signature scans remain; a cross-tier cache would
  be unsound after an earlier install, so the startup cost is measured rather
  than cached.
