# AGENTS.md — readable-fusion-opcep

A fork of `readable-fusion` (the proved 1:1 ZolikaPatch 7.65 replacement) that
implements the OpenPreCEPatch improvements as named, revertable overlays. The
oracle is still `../game_refs/ZolikaPatch_original.asi.off`; the reference for
*what* to add is `../openprecepatch/source/` and its docs. The old `../readable/`
tree is a secondary reference only and its source is never copied.

**Distribution identity.** The artifact is `IV.EFLC.OpenPreCEPatch.asi` and the
shipped configuration is OpenPreCEPatch's grouped
`data/plugins/IV.EFLC.OpenPreCEPatch.ini`, resolved next to the ASI and parsed
through `Feather::LoadGrouped` (trailing `//`/`;` comments and over-256-byte
lines are normalised; the original grammar and its 256-byte fault stay in
`Feather::Load` for the flat file). The root `ZolikaPatch.ini` is the parity /
legacy configuration the oracle tools use and is never the shipped file.

## Current state

The 99-key catalogue from `readable-fusion` is intact and proved on 1.0.8.0:
98 keys closed, one oracle-verified by construction (`SkipLauncher`), the
transcribed bodies still compare instruction-for-instruction,
`tools/parity_report.py 9` is unchanged, and the 34 native/ctest targets pass.
On top of that:

- `source/improvements.ixx` is the `OPCEP_IMPROVEMENTS` switch. Unset means the
  1:1 path; `all` is the folded set, which is only `failsafe`; every other group
  is named; `except:failsafe` is the 1:1 fault configuration.
- `failsafe` (folded): install-time missing-pointer/site/body guards on the
  recovered arms, plus P13 match-count checks. A transcribed body is never
  rewritten, so a guard is an install refusal (the un-patched game path), not a
  body edit.
- `shader`, `alpha_nop`, `opcep`, `nms`, `config`, `warnings`, `ooc_cache`,
  `hardening`, `sco_anchor`, `garage_entry`, `cutscene_entry`, `caches`,
  `dlc_path`, `import`, `task_dialogs`: the source-derived OpenPreCEPatch
  changes, each outside `all` because it changes a user-visible outcome.
  `docs/improvements.md` is the audit: every option OpenPreCEPatch adds, removes
  or moves, every changed default, and every implementation delta with its
  disposition. `nms` carries the **MMA10** fix: the original's ownership test is
  a range, NMS's exact set turned an interior/double free into
  `lmsgboxExit("MMA10")`; `docs/mma10.md` has the minidump evidence and the
  page-map fix. `hardening` is the validated NewSavesCompatibility walk.
- `docs/version-matrix.md` + `tests/parity/applicability.tsv` are generated by
  `tools/gen_applicability.py` from `source/options.inc` and
  `data/applicability_evidence.json`; `--check` is a ctest. `Loader::Enabled`
  refuses every build outside a key's mask and every `unknown` build
  (`zp_applicability`).
- The three OpenPreCEPatch-only compatibility features are in the `opcep`
  group: `GFWLProtectionDisabler` (`misc.ixx`), `SteamAchievements`
  (`source/steam.ixx`) and the unified `RemoveModChecks` alias. They are outside
  the recovered 99-key catalogue; the shipped INI carries their keys, and the
  group decides whether they act.

## Non-negotiables

- **1:1 is the default.** Every divergence is a named group and every group can
  be left off. A guard must never change a fault outcome in the 1:1
  configuration; `tools/check_failsafe_parity.py` proves a healthy image's write
  set is identical with the failsafe on and off, and the 1.0.0.0 NoImpostor cell
  faults only with the group off.
- **Do not edit** `../readable-fusion/`, `../openprecepatch/`,
  `../openprecepatch/xlivelessaddon/`, `../ZolikaPatch_reconstruction/` or
  `../GTAIV/`. Copy from them, never modify them. Nothing is copied out of
  `../readable/`.
- **Recovered data may be reused** (signatures, byte rows, RVAs, offsets,
  defaults, achievement ids/names, recovered vtable indices) with a provenance
  comment; every executable line is written fresh.
- **Startup stays synchronous in `DllMain`.** The warnings group shows a
  synchronous message box; the Steam bridge initialises lazily on the first
  achievement write, never in `DllMain`. The shipped ASI writes no log; tracing
  exists only in the `Trace` configuration (`ZP_TRACE`).
- **One commit per change, revertable.** Every commit message ends with a
  `Revert:` line naming the tag before it; a change that rewrites an entry
  point, a body contract or the write set keeps the original path compiled and
  selectable.
- **Readable first, assembly in a marked tail.** MSVC rejects
  `__declspec(naked)` on a declaration (C2488): prototypes are plain `static`,
  only the tail definition keeps the attribute. Registration order inside a
  `Register<Key>` is behavioural and never changes.

## Build and test

```
cmake --preset win-x86
cmake --build --preset release
ctest --preset release
```

Win32/MSVC only, static CRT, base `0x10000000`, windowed subsystem. The
artifact is `build/win-x86/Release/IV.EFLC.OpenPreCEPatch.asi`, with
`IV.EFLC.OpenPreCEPatch.ini` copied beside it; `Trace` builds the same ASI with
tracing on.

Measurement tools, in the order the evidence is built:

```
python tools/parity_report.py 9            # per-key scoreboard on 1.0.8.0
python tools/dump_matrix.py                # 9 builds x (full, per-option)
python tools/check_failsafe_parity.py --dump build/win-x86/Release/zp_dump.exe --game ../game_refs
python tools/check_opcep_deltas.py --dump build/win-x86/Release/zp_dump.exe --game ../game_refs
python tools/gen_applicability.py --check
python tools/check_signature_parity.py --game ../game_refs
python tools/check_relocated_literals.py --game ../game_refs
python tools/check_oracle_verified.py
```

`zp_failsafe` is the switch/guard unit test (including the same null
dereference in a child under both configurations), `zp_config_guard` the config
group's both-sides test, `zp_steam` the achievement table/refusal,
`zp_warnings` the version/mutex/notice probes, `zp_applicability` the
build-refusal rule, `zp_caches` the model-lookup memo, `zp_import` the grouped
INI creation/preference, `zp_dlc_path` the 0x104-byte path bound, and
`zp_ooc_init`/`zp_nms_arena`/`zp_save_walk` the cache, allocator and save
groups, and `zp_shipped_ini` the shipped grouped file's comment/over-256-byte
normalisation.
