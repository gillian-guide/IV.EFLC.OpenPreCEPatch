# AGENTS.md — readable-fusion-opcep

A fork of `readable-fusion` (the proved 1:1 ZolikaPatch 7.65 replacement) that
ships as OpenPreCEPatch: the improvements are compiled in, and the keys
OpenPreCEPatch removed or moved to XLivelessAddon are out. The oracle for a
retained arm is still `../game_refs/ZolikaPatch_original.asi.off`; the reference
for *what* to add is `../openprecepatch/source/` and its docs. The old
`../readable/` tree is a secondary reference only and its source is never
copied.

**Distribution identity.** The artifact is `IV.EFLC.OpenPreCEPatch.asi` and the
shipped configuration is OpenPreCEPatch's grouped
`data/plugins/IV.EFLC.OpenPreCEPatch.ini`, resolved next to the ASI and parsed
through `Feather::LoadGrouped` (trailing `//`/`;` comments and over-256-byte
lines are normalised; the original grammar and its 256-byte fault stay in
`Feather::Load` for the flat file). The flat `tests/parity/ZolikaPatch.ini` is an
internal regression fixture, not a shipped file.

## Current state

The 84-key catalogue is the OpenPreCEPatch surface: the ZolikaPatch 7.65 behavior
with the improvements compiled in, minus the keys OpenPreCEPatch removed or moved
to XLivelessAddon (15 keys: AddOptionsInMenu, FixPCIDKickbug,
ForceDynamicShadowsEverywhere, HighQualityReflections, MiscFixes, NoPhysicsSleep,
RemoveBoundingBoxCulling, RemoveUselessChecks, BorderlessWindowed,
DoNotPauseOnMinimize, LocalSettingsPath, SkipIntro, SkipLauncher, SkipMenu,
VRAMFix). There is no runtime improvement switch; `git revert` of the integration
commit is the rollback. The remaining 146-body proof passes for the retained
bodies, `tools/parity_report.py 9` scores the retained keys, and the 37
native/ctest targets pass. On top of that:

- The install-time failsafes and the P13 count checks are unconditional
  (`patch.ixx`: `Failsafe`, `SetMissingForTest`, `ExpectMatchCount`). A missing
  pointer, a site outside the image or an unresolved body refuses the install;
  a transcribed body is never rewritten.
- The config reads never throw: a bad value falls back to the option default and
  is counted once; a bad model-table row keeps its hash and zero value. The
  FusionFix overlap gate is always applied when a FusionFix ASI is present.
- `shader` only replaces the two LookupShader calls; `alpha_nop` removes the
  `jnz` alone; the popup check is a C++ memoised resolver/angle scan; the model
  lookup is a 64-bit atomic memo; the 38,455-name model table has a sorted hash
  index; GarageModelFix hooks the prologue; CutsceneFixes relocates the shared
  callee; SCOSignatureFix scans the branch anchor; LoadDLCs uses the checked
  path discovery; NewMemorySystem uses the private heap and page map;
  NewSaves validates the walk; the warnings use TaskDialogIndirect; the model
  lookup, Steam bridge, NMS and OOC caches are thread-safe; `launcher` rewrites
  only the two recovered `LaunchGTAIV.exe` slots of the five gated builds (a
  whole-image scan: the slots are `.rdata`), after the handler's `PlayGTAIV.exe`
  process walk -- this is what keeps a `PlayGTAIV.exe`-launched 1.0.8.0 out of
  the `lmsgboxExit("SRLC10")` dialog.
- The recovered-behaviour notes at the end of this file record the two measured
  baseline omissions the scoreboard excuses.
- `tests/parity/applicability.tsv` is generated by `tools/gen_applicability.py`
  from `source/options.inc` and `data/applicability_evidence.json`; `--check` is
  the `zp_applicability_drift` ctest. `Loader::Enabled` refuses every build
  outside a key's mask and every `unknown` build (`zp_applicability`).
- The three OpenPreCEPatch-only compatibility features are always compiled:
  `GFWLProtectionDisabler` (module-image guarded), `SteamAchievements` (the
  xlive ordinal-5278 boundary) and the unified `RemoveModChecks` alias.

## Non-negotiables

- **The OpenPreCEPatch surface is the product.** The improvements are compiled in,
  the 15 removed/moved keys stay out, and a behavior change is a normal commit
  with a `Revert:` line; there is no runtime switch to fall back to. A retained
  arm's write set is still proved by the dump against the recovered baseline;
  a deliberate improved delta (shader, alpha, DLC paths, entry points) is
  documented in this file and the commit message, not silently accepted.
- **Do not edit** `../readable-fusion/`, `../openprecepatch/`,
  `../openprecepatch/xlivelessaddon/`, `../ZolikaPatch_reconstruction/` or
  `../GTAIV/`. Copy from them, never modify them. Nothing is copied out of
  `../readable/`.
- **Recovered data may be reused** (signatures, byte rows, RVAs, offsets,
  defaults, achievement ids/names, recovered vtable indices) with a provenance
  comment; every executable line is written fresh.
- **Startup stays synchronous in `DllMain`.** The warnings use a synchronous
  task dialog; the Steam bridge initialises lazily on the first achievement
  write, never in `DllMain`. The shipped ASI writes no log; tracing exists only
  in the `Trace` configuration (`ZP_TRACE`).
- **One commit per change, revertable.** Every commit message ends with a
  `Revert:` line naming the tag before it. A change that rewrites an entry point
  or a body contract is proved by the dump and the body proof before the old
  path is deleted.
- **Readable first, assembly in a marked tail.** MSVC rejects
  `__declspec(naked)` on a declaration (C2488): prototypes are plain `static`,
  only the tail definition keeps the attribute. Registration order inside a
  `Register<Key>` is behavioural and never changes.

## Build and test

```
cmake --preset win-x86
cmake --build --preset release
ctest --preset release
```

Win32/MSVC only, static CRT, base `0x10000000`, windowed subsystem. The
artifact is `build/win-x86/Release/IV.EFLC.OpenPreCEPatch.asi`, with
`IV.EFLC.OpenPreCEPatch.ini` copied beside it; `Trace` builds the same ASI with
tracing on.

Measurement tools, in the order the evidence is built:

```
python tools/parity_report.py 9            # per-key scoreboard on 1.0.8.0
python tools/dump_matrix.py                # 9 builds x (full, per-option)
python tools/gen_applicability.py --check
python tools/check_signature_parity.py --game ../game_refs
python tools/check_relocated_literals.py --game ../game_refs
python tools/check_oracle_verified.py
```

`zp_failsafe` the guard unit test, `zp_launcher` the launcher payload/sites/probe
and two-slot rule, `zp_launcher_dump` that write set on the nine real images,
`zp_config_guard` the config group's
behavior, `zp_steam` the achievement table/refusal, `zp_warnings` the
version/mutex/notice probes, `zp_applicability` the build-refusal rule,
`zp_caches` the model-lookup memo, `zp_import` the grouped INI
creation/preference, `zp_dlc_path`/`zp_dlc_full` the DLC bound and checked
discovery, `zp_module_guard` the GFWL module-offset guard, `zp_loader_info` the
UAL 6.9.0 threshold, `zp_model_index`/`zp_popup_cache` the two caches,
`zp_shipped_ini` the shipped grouped INI, `zp_fchs` the checked FCHS walk, and
`zp_ooc_init`/`zp_nms_arena`/`zp_save_walk` the cache, allocator and save
groups.

## Recovered-behaviour notes

### The noE fill: CarDynamicShadowFix on 1.0.0.0 and 1.0.4.0

On the two builds where pattern E is absent, the original writes a six-byte
`90 90 90 90 90 90` fill at the C anchor's +0x3E, and this tree writes it too.
The stored baseline has no row there because the reference tree's
`ApplyCarDynamicShadowFixNoE` pass was defined but never wired into the dump that
produced it. The row is therefore per key and per build, and the key is scored
normally everywhere else -- it is closed on 1.0.8.0.

### Patch7RemoveModChecks: the OR, an alternate handler

The original has no Patch7 handler of its own: `0x100523C0` ORs
`Patch7RemoveModChecks` into `Patch6and7`'s handler `0x10044710`, so a Patch7-only
INI runs the full 16-byte (1.0.6.0) / 21-byte (1.0.7.0) write set. The stored
baseline records the reference tree's own smaller 5-byte / two-jump, 10-byte arm
instead, so the key is excused on 1.0.6.0 and 1.0.7.0 only, and the baseline's
write set is a strict subset of this tree's.
